Show a picture.
Read it in ខ្មែរ.

Tossana (ទស្សនៈ, "seeing") will describe photos in Khmer: what is in the picture, who is doing what, and where. Small enough to run on a phone without internet, so it can help people who cannot see the screen, and your photos never leave the device.

Why

Describing pictures in Khmer is hard for a machine

Today's captioning models were trained almost only on English. Khmer brings problems they never see.

No Khmer caption data

There is no large open set of photos with Khmer descriptions. Tossana starts from English captions translated to Khmer, with the test set checked by people.

No spaces between words

Khmer is written without spaces, so word-based scores do not fit. Tossana is scored on Khmer letter clusters, the same units Chakkhu and Sota use.

Seeing things that are not there

Small captioning models often name objects that are not in the photo. For someone who cannot see the picture, a wrong object is worse than a short caption.

Architecture · the plan

A small eye that speaks Khmer

About 33 million parameters: a pretrained ViT-S image encoder, a small decoder that writes Khmer clusters, a fast concept head and a guard against invented objects. It shares Sota's recipe: Khmer clusters as tokens, int8 ONNX, beam search.

Figure 1. Overview (planned design). 16×16 patches → 12 ViT blocks → a concept head (object tags) and a 4-layer caption decoder → beam search that drops any caption naming an object the concept head does not see.

Why this design

  • Starts from a trained eye. The ViT-S encoder already knows images (ImageNet); only the Khmer writer is learned from scratch.
  • Whole clusters, not letters. The same 3,402 Khmer cluster tokens as Chakkhu and Sota, so ស្ត្រី is one token and all three share one engine.
  • Checks itself. A small concept head lists the objects it sees; captions that name anything else are dropped (planned, the main research idea).
  • Runs on the phone. Encoder and decoder are exported to int8 ONNX, like Sota; the English test model already runs this way on a laptop CPU.

Results · step 1 of the plan

Before making Khmer data, we trained the same design in English on Flickr8k (6,000 training photos, 5 captions each) and scored it on the 1,000 test photos. These are not Khmer results. Khmer scores come after the Khmer captions are ready.

What CIDEr means

How well a caption uses the words most people chose for that photo; rare, informative words count more. 0 to about 150; higher is better.

Is this good?

For a small model trained only on Flickr8k, yes: the classic Show, Attend and Tell model reported BLEU-4 ≈ 21 on the same test photos (we get 25.5). Large models trained on far more data score higher.

What we will report for Khmer

CIDEr and BLEU-4 on Khmer clusters, how often captions name objects that are not there, and size and speed on a phone.

Roadmap

Where we are

One step at a time, each with a check before the next.

Done

Name & design

Tossana ទស្សនៈ, the ≈33M design and the architecture figure.

Done

English test run

Same pipeline in English on Flickr8k: CIDEr 65.9, exported to int8 ONNX, ONNX and PyTorch give the same captions.

Done

Translation tools

Notebook that translates captions to Khmer, flags bad ones and prepares a test set for people to check.

Now

Khmer captions

Pick the translator, translate Flickr8k, then people check 2,000 test captions.

Next

First Khmer model

Train on Khmer clusters, score it, then add the concept head and the guard against invented objects.

Later
